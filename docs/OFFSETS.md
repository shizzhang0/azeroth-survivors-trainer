# 偏移表

所有偏移都经过**差分快照**或**写入验证**，不是猜的。代码里的唯一来源是 [`src/offsets.py`](../src/offsets.py)，改偏移只改那里。游戏版本间会变，变了的处理见 [UPDATING.md](UPDATING.md)。

## 一、属性块（`trainer.py` 用）

一块连续的 `f32`，独立分配，游戏会周期性用计算值覆盖它。

| 偏移 | 字段 | 说明 |
|---|---|---|
| `+0x00` | hp | 最大生命 |
| `+0x04` | dmg | 伤害倍率 |
| `+0x08` | cd | 冷却倍率（越小越快） |
| `+0x0C` | crit | 暴击率 |
| `+0x10` | cm | 暴击伤害倍率 |
| `+0x14` | spd | 移动速度 |
| `+0x18` | pick | 拾取半径 |
| `+0x1C` | xp | 经验倍率 |
| `+0x20` | arm | 减伤 |
| `+0x24` | ??? | **v1033 起新增，值恒为 0.6，含义未知，不要写**。和面板“生命偷取 0.6%”数值巧合，但 v1118 写 0.07、3.0 时吸血都没变，所以不是吸血 |
| `+0x28` | reg | 每秒回血 |
| `+0x2C` | area | 范围倍率 |
| `+0x30` | luck | 幸运 |
| `+0x34` | gold | 金币倍率 |
| `+0x38` | targets | 额外目标数（**i32 整数**），面板“目标数 +N” |
| `+0x3C` | echo | 回响（0.22 = 22%） |
| `+0x40` | heal | 击杀治疗（面板显示整数） |
| `+0x44` | bp | 增益强度（0.44 = +44%） |
| `+0x48` | dots | **额外**持续伤害层数（i32）；面板显示 min(值, 3) + 1，最多 4 层（早先写 f32 55 被读成巨大整数，于是显示 4） |
| `+0x4C` | doth | 持续伤害急速（0.77 = +77%） |

> `+0x38` 起这几项在 v1118 上用“写标记值、看角色面板”逐个确认（目标数 +7 / 回响 22% / 击杀治疗 33 / 增益强度 +44% / 持续伤害急速 +77%）。
| `+0x60` | lives | 生命数（i32） |

> `+0x48`、`+0x60` 是从游戏打印属性行的代码（RVA `0x5F5E950`，`lch=`/`thn=`/`liv=`/`dots=` 的取值处）反推出来，再写标记值在面板上确认的（生命数 3、持续伤害层数 3）。

**荆棘**不在属性块里：游戏每次把装备/卡牌**效果列表**里 tag `0x16` 的条目加起来。列表是个 Vec，指针在玩家对象 `+0xADC`、长度在 `+0xAE4`，每项 8 字节（u8 tag、3 字节填充、f32 数值）。工具改的是第一条 `0x16` 条目，使总和等于目标值；没有任何荆棘来源时改不了。实测 30% → 77%。
**生命偷取**由四部分相加（RVA `0x5F809D0`）：限时叠层增益 + 职业基础（exe 里的常量表，圣骑士 0.6%）+ 效果列表 tag `0x0e` + **物品列表**里定义类型为 `0x12` 的物品（饰品，如饮血者指环，传说品质 3.0%）。
物品列表也是 Vec：指针在玩家对象 `+0x43C`、长度在 `+0x444`，每项 24 字节，`+0x00` 指向物品定义（类型字节在定义 `+0x44`），`+0x10` 是数值。
工具只改两个列表的部分（面板上叫“生命偷取（装备部分）”），游戏面板的总值还要加上职业基础；没有吸血装备/饰品时改不了。
2026-11-06 实测：拿到传说饮血者指环后物品列表多出一项（类型 `0x12`、数值 0.03），改成 0.25 后角色面板的生命偷取同步变成 25% + 职业基础，且不会被游戏改回（物品数值是真实状态，不是重算缓存）。

> v0.2.0-977 及更早：`+0x24` 处是 `reg`，之后整体前移 4 字节（`reg +0x24 / area +0x28 / luck +0x2C / gold +0x30`）。

## 二、玩家对象（`player.py` 用）

一个几 KB 的大对象，属性块嵌在它内部（`对象基址 + 0x5F4 = 属性块起点`）。

| 偏移 | 类型 | 字段 | 验证方式 |
|---|---|---|---|
| `+0x58C` | i32 | 等级 | 差分（升级 18→20） |
| `+0x590` | i32 | 当前经验 | 差分（升级后清零） |
| `+0x594` | f32 | 当前血量 | 写入后血条回满 |
| `+0x5A4` | i32 | 金币数量 | 写入 999999 → HUD 跟随 |
| `+0x658` | i32 | 重抽次数 | 实测重抽 5→4，HUD 一致 |
| `+0x5F4` | f32 | 最大血量 | 差分 + 写入 |
| `+0xA3C` | i32 | 击杀数 | v1039 起：与 HUD 同步（222→268；1115、1118 复核）；≤1036 在 `+0x974` |
| `+0x1050` | i32 | 放逐次数 | v1115 实测放逐 3→2，唯一一个恰好减 1 的槽位；1118 复核；1036 在 `+0xF5C` |
| `+0x1024` | i32 | 宝箱价格（下一个宝箱要花的金币，HUD `chestCost`） | v1115：开一个宝箱 20→31；写入 1 → HUD 显示 1，开箱只扣 1；1118 复核 |

属性块相对对象基址的完整布局：

```
+0x5F4 hp    +0x5F8 dmg   +0x5FC cd    +0x600 crit  +0x604 cm
+0x608 spd   +0x60C pick  +0x610 xp    +0x614 arm   +0x618 ?(0.6)
+0x61C reg   +0x620 area  +0x624 luck  +0x628 gold_mult
```

## 三、定位方法

### 属性块

拿属性行里的 `cm`（暴击伤害）当锚点——`cm` 固定在 `+0x10`，减去 0x10 就是块起点，
再校验 `+0x00≈hp / +0x20≈arm / +0x2C≈area / +0x30≈luck`。

⚠️ **不要用 `hpMax` 当唯一锚点**：属性行滞后于内存，升级瞬间能差 10%。

### 玩家对象

**结构指纹 + HUD 交叉验证**：

1. 在候选基址的 `+0x604 ~ +0x620` 上，七个属性字段必须同时落在合理区间
   （cm 1~20、spd 0.5~20、pick 1~800、xp 0.5~20、arm 0~2、reg 0~5000、area 0.2~30）；
2. 用 HUD 的**击杀数**（±5%）或**金币**（±10%）确认唯一命中；
3. 校验 `当前血 ≤ 最大血`、`1 ≤ 等级 < 200`。

范围要放宽——高等级角色的拾取、回复能到几百，范围设窄了会找不到。

## 四、为什么 `-1/+1` 差分能定字段

游戏里同一时刻只有少数计数器会变，且**只增不减**（击杀、金币、经验）。
所以：

- 找一个**减少 1** 的小整数 → 重抽/放逐这类“剩余次数”；
- 找两个属性行数值同时吻合的槽位 → 金币、等级。

`+0x658`（重抽）和 `+0x1050`（放逐）就是这样定出来的：一个槽位、变化量恰为 1、其余无干扰。
