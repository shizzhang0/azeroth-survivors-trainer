# 偏移表

所有偏移都经过**差分快照**或**写入验证**，不是猜的。游戏版本间会变，变了的处理见 [UPDATING.md](UPDATING.md)。

## 一、属性块（`trainer.py` 用）

一块连续的 `f32`，独立分配，游戏会周期性用计算值覆盖它。

| 偏移 | 字段 | 说明 |
|---|---|---|
| `+0x00` | hp | 最大生命 |
| `+0x04` | dmg | 伤害倍率 |
| `+0x08` | cd | 冷却倍率（越小越快） |
| `+0x0C` | crit | 暴击率 |
| `+0x10` | cm | 暴击伤害倍率 |
| `+0x14` | spd | 移动速度 |
| `+0x18` | pick | 拾取半径 |
| `+0x1C` | xp | 经验倍率 |
| `+0x20` | arm | 减伤 |
| `+0x24` | ??? | **v1033 起新增，值恒为 0.6，面板不显示，含义未知，不要写** |
| `+0x28` | reg | 每秒回血 |
| `+0x2C` | area | 范围倍率 |
| `+0x30` | luck | 幸运 |
| `+0x34` | gold | 金币倍率 |

> v0.2.0-977 及更早：`+0x24` 处是 `reg`，之后整体前移 4 字节（`reg +0x24 / area +0x28 / luck +0x2C / gold +0x30`）。

## 二、玩家对象（`player.py` 用）

一个几 KB 的大对象，属性块嵌在它内部（`对象基址 + 0x5F4 = 属性块起点`）。

| 偏移 | 类型 | 字段 | 验证方式 |
|---|---|---|---|
| `+0x58C` | i32 | 等级 | 差分（升级 18→20） |
| `+0x590` | i32 | 当前经验 | 差分（升级后清零） |
| `+0x594` | f32 | 当前血量 | 写入后血条回满 |
| `+0x5A4` | i32 | 金币数量 | 写入 999999 → HUD 跟随 |
| `+0x658` | i32 | 重抽次数 | 实测重抽 5→4，HUD 一致 |
| `+0x5F4` | f32 | 最大血量 | 差分 + 写入 |
| `+0x974` | i32 | 击杀数 | 差分（620→737） |
| `+0xF5C` | i32 | 放逐次数 | 实测放逐 3→2，全对象唯一减 1 |

属性块相对对象基址的完整布局：

```
+0x5F4 hp    +0x5F8 dmg   +0x5FC cd    +0x600 crit  +0x604 cm
+0x608 spd   +0x60C pick  +0x610 xp    +0x614 arm   +0x618 ?(0.6)
+0x61C reg   +0x620 area  +0x624 luck  +0x628 gold_mult
```

## 三、定位方法

### 属性块

拿属性行里的 `cm`（暴击伤害）当锚点——`cm` 固定在 `+0x10`，减去 0x10 就是块起点，
再校验 `+0x00≈hp / +0x20≈arm / +0x2C≈area / +0x30≈luck`。

⚠️ **不要用 `hpMax` 当唯一锚点**：属性行滞后于内存，升级瞬间能差 10%。

### 玩家对象

**结构指纹 + HUD 交叉验证**：

1. 在候选基址的 `+0x604 ~ +0x620` 上，七个属性字段必须同时落在合理区间
   （cm 1~20、spd 0.5~20、pick 1~800、xp 0.5~20、arm 0~2、reg 0~5000、area 0.2~30）；
2. 用 HUD 的**击杀数**（±5%）或**金币**（±10%）确认唯一命中；
3. 校验 `当前血 ≤ 最大血`、`1 ≤ 等级 < 200`。

范围要放宽——高等级角色的拾取、回复能到几百，范围设窄了会找不到。

## 四、为什么 `-1/+1` 差分能定字段

游戏里同一时刻只有少数计数器会变，且**只增不减**（击杀、金币、经验）。
所以：

- 找一个**减少 1** 的小整数 → 重抽/放逐这类“剩余次数”；
- 找两个属性行数值同时吻合的槽位 → 金币、等级。

`+0x658`（重抽）和 `+0xF5C`（放逐）就是这样定出来的：一个槽位、变化量恰为 1、其余无干扰。
