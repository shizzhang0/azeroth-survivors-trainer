# 偏移表

所有偏移都经过**差分快照**或**写入验证**，不是猜的。代码里的唯一来源是 [`src/offsets.py`](../src/offsets.py)，改偏移只改那里。游戏版本间会变，变了的处理见 [UPDATING.md](UPDATING.md)。

## 一、属性块（`trainer.py` 用）

一块连续的 `f32`，独立分配，游戏会周期性用计算值覆盖它。

| 偏移 | 字段 | 说明 |
|---|---|---|
| `+0x00` | hp | 最大生命 |
| `+0x04` | dmg | 伤害倍率 |
| `+0x08` | cd | 冷却倍率（越小越快） |
| `+0x0C` | crit | 暴击率 |
| `+0x10` | cm | 暴击伤害倍率 |
| `+0x14` | spd | 移动速度 |
| `+0x18` | pick | 拾取半径 |
| `+0x1C` | xp | 经验倍率 |
| `+0x20` | arm | 减伤 |
| `+0x24` | ??? | **v1033 起新增，值恒为 0.6，含义未知，不要写**。和面板“生命偷取 0.6%”数值巧合，但 v1118 写 0.07、3.0 时吸血都没变，所以不是吸血 |
| `+0x28` | reg | 每秒回血 |
| `+0x2C` | area | 范围倍率 |
| `+0x30` | luck | 幸运 |
| `+0x34` | gold | 金币倍率 |
| `+0x38` | targets | 额外目标数（**i32 整数**），面板“目标数 +N” |
| `+0x3C` | echo | 回响（0.22 = 22%） |
| `+0x40` | heal | 击杀治疗（面板显示整数） |
| `+0x44` | bp | 增益强度（0.44 = +44%） |
| `+0x48` | dots | **额外**持续伤害层数（i32）；面板显示 min(值, 3) + 1，最多 4 层（早先写 f32 55 被读成巨大整数，于是显示 4） |
| `+0x4C` | doth | 持续伤害急速（0.77 = +77%） |

> `+0x38` 起这几项在 v1118 上用“写标记值、看角色面板”逐个确认（目标数 +7 / 回响 22% / 击杀治疗 33 / 增益强度 +44% / 持续伤害急速 +77%）。
| `+0x60` | lives | 生命数（i32） |

> `+0x48`、`+0x60` 是从游戏打印属性行的代码（RVA `0x5F5E950`，`lch=`/`thn=`/`liv=`/`dots=` 的取值处）反推出来，再写标记值在面板上确认的（生命数 3、持续伤害层数 3）。

**荆棘**不在属性块里：游戏每次把**效果列表**里 tag `0x16` 的条目加起来。效果列表就是这局带进来的**天赋通用属性**（军械库里点的）：**每种属性一条**，同类天赋先加在一起（神圣强化 5/5 + 定罪 5/5 → 一条暴击 12.5%）。开局时一条条 push 进去，局内拿技能卡、装备卡都不会动它；里程碑天赋和只作用于某个技能的天赋（强化审判、圣洁光环……）不在这里。
列表是个 Rust Vec：容量在玩家对象 `+0xAD4`、指针在 `+0xADC`、长度在 `+0xAE4`，每项 8 字节（u8 tag、3 字节填充、f32 数值）。容量按 4、8、16 翻倍，所以天赋涉及 7 种属性时容量 8、有 1 个空位，8 种时正好满。

| tag | 属性 | v1118 圣骑士的来源（实测数值） |
|---|---|---|
| `0x00` | 全部伤害 | 强化力量祝福 5/5 = 5%，+ 神圣之力 5/5 → 12.5% |
| `0x01` | 冷却加快 | 祈福 5/5 = 7.5%（天赋说明确认） |
| `0x02` | 最大生命 | 盾牌壁垒 2/5 = 8% |
| `0x03` | 暴击几率 | 定罪 5/5 = 7.5%，+ 神圣强化 5/5 → 12.5% |
| `0x04` | 暴击伤害 | 辩护 3/3 = 12% |
| `0x05` | 受到伤害降低 | 强化虔诚光环 5/5 + 偏斜 5/5 = 10%；不屈信仰 3/3 + 偏斜 2/5 = 5.6% |
| `0x06` | 每秒回复（点数，不是 %） | 神圣智慧 1/5 = 0.4 |
| `0x07` | 移动速度 | 正义追击 2/2 = 8% |
| `0x0e` | 生命偷取 | 精神协调（防护第 2 排右，防护投入 5 点后可点，第 1 级 0.25%，最多 3 级）；追加一条 0.10，面板 0.6% → 10.6% |
| `0x16` | 荆棘 | 以眼还眼 3/3 = 30% |

v1127 补测（2026-11-09）：圣骑士一局里依次追加 `(tag, 3.0)`，等游戏重算一次属性块，再撤掉、再重算一次，比较两次：

| tag | 属性 | 追加 3.0 后 |
|---|---|---|
| `0x08` | 范围 | 1.193 → 4.193 |
| `0x09` | 拾取 | 34.8 → 139.2 码（乘 1+3） |
| `0x0a` | 经验值 | 1 → 4 |
| `0x0b` | 金币 | 1.147 → 4.147 |
| `0x0c` | **幸运** | 0 → 3 |
| `0x0d` | 回响 | 0 → 3 |
| `0x0f` | 击杀治疗 | 0 → 3 |

`0x10` 那次暴击 0.35 → 0.29，像是测试时恰好选了卡，不算数；`0x11` 起没测完（那局结束了）。
重算时机用一个标记值判断：等待前把回复写成 777，属性块被重算时它会被盖掉。

**幸运为什么要放进这个列表**：游戏在升级、选卡时重算属性块，并在同一帧发出下一手牌（攒了好几级时）。
同一局的时间线（v1127）：每次选卡后幸运变 0，约 15 毫秒后锁定才写回；13～18 毫秒后发出的手牌是普普普、优优优，
而离重算几百毫秒的第一手是传史史。锁定改成同时在列表里放一条 `0x0c` 后，连续出的手牌也都是传说和史诗。

对照方法：exe 里有天赋定义表（id、英文名、图标、`{v}` 描述模板、最高等级和行列），中文名在 exe 自带的翻译 JSON 里；再拿两套不同加点下的列表互相比对。
**生命偷取**由四部分相加（RVA `0x5F809D0`）：限时叠层增益 + 职业基础（exe 里的常量表，圣骑士 0.6%）+ 效果列表 tag `0x0e` + **物品列表**里定义类型为 `0x12` 的物品（饰品，如饮血者指环，传说品质 3.0%）。
物品列表也是 Vec：指针在玩家对象 `+0x43C`、长度在 `+0x444`，每项 24 字节，`+0x00` 指向物品定义（类型字节在定义 `+0x44`），`+0x10` 是数值。
物品列表是正常追加的：拿一件装备，长度 1 → 2，指针、容量（4）都不变。

**工具怎么改这两项**（`session._write_effect`）：
1. 效果列表有空位时，在末尾**新增一条我们自己的条目**（荆棘用 tag `0x16`，生命偷取用 `0x0e`），值 = 目标 − 现有来源之和，再把长度 +1。天赋、卡、饰品的数值都不动；解锁时这条是最后一条就把长度减回去，后面还有别的条目就改成 0。
2. 没有空位时（一个通用属性天赋都没点：容量 0、指针是 Rust 空数组的占位值 `4`；或正好 4、8 种），**把列表搬到我们自己的一页内存**：
   - 用 `VirtualAllocEx` 在游戏里申请 4 KB，复制原有条目，加上我们那条；
   - 先把容量写成 **0**，再改指针、长度。Rust 只在容量不为 0 时释放 Vec 的内存，所以游戏永远不会把我们这页交给它的分配器；原来那块内存也不会被释放，留着等还原；
   - 全部解锁（或关掉后台）时按"长度 → 指针 → 容量"的顺序指回原来那块。开了新的一局（列表已经不是我们那页）就什么都不写。
   - 这一页不释放，每次搬家多占 4 KB，到游戏退出为止。
3. 申请不到内存时才退回改第一个现有来源，记住原值、解锁写回；连来源都没有就报错，不写。

2026-11-06 实测（v1118）：德鲁伊不点任何通用属性天赋（空列表）、圣骑士满天赋 8 种（满列表），荆棘和生命偷取都能锁上，解锁回到原值；锁着打完整局、回菜单、再开一局都没有崩溃。

生命偷取面板上叫“生命偷取（不含基础）”，游戏面板的总值还要加上职业基础和限时增益。

2026-11-06 实测（v1118）：
- 传说饮血者指环：物品列表多出一项（类型 `0x12`、数值 0.03），改成 0.25 后角色面板的生命偷取变成 25% + 职业基础，不会被改回。
- 拿掉荆棘天赋（7 条数值天赋，容量 8）：追加一条 `(0x16, 0.5)` 并把长度改成 8，面板荆棘从 0 变成 50%。

> v0.2.0-977 及更早：`+0x24` 处是 `reg`，之后整体前移 4 字节（`reg +0x24 / area +0x28 / luck +0x2C / gold +0x30`）。

## 二、玩家对象（`player.py` 用）

一个几 KB 的大对象，属性块嵌在它内部（`对象基址 + 0x5F4 = 属性块起点`）。

| 偏移 | 类型 | 字段 | 验证方式 |
|---|---|---|---|
| `+0x58C` | i32 | 等级 | 差分（升级 18→20） |
| `+0x590` | i32 | 当前经验 | 差分（升级后清零） |
| `+0x594` | f32 | 当前血量 | 写入后血条回满 |
| `+0x5A4` | i32 | 金币数量 | 写入 999999 → HUD 跟随 |
| `+0x658` | i32 | 重抽次数 | 实测重抽 5→4，HUD 一致 |
| `+0x5F4` | f32 | 最大血量 | 差分 + 写入 |
| `+0xA3C` | i32 | 击杀数 | v1039 起：与 HUD 同步（222→268；1115、1118 复核）；≤1036 在 `+0x974` |
| `+0x1050` | i32 | 放逐次数 | v1115 实测放逐 3→2，唯一一个恰好减 1 的槽位；1118 复核；1036 在 `+0xF5C` |
| `+0xFC4` | f32 | 局内计时（秒，HUD `time`；极速模式用） | v1127：按 HUD 时间找到、给它加 30 秒 HUD 跟着跳；两局都在这里（第二局计时 +0x60 正好是宝箱价格） |
| `+0x1024` | i32 | 宝箱价格（下一个宝箱要花的金币，HUD `chestCost`） | v1115：开一个宝箱 20→31；写入 1 → HUD 显示 1，开箱只扣 1；1118 复核 |

```
+0x608 spd   +0x60C pick  +0x610 xp    +0x614 arm   +0x618 ?(0.6)
+0x61C reg   +0x620 area  +0x624 luck  +0x628 gold_mult
```

## 三、局内计时（极速模式用）

HUD 的 `"time"`（局内时间，首领 8:00、14:00 按它来）是玩家对象 `+0xFC4` 的一个 **f32**（见上表）。最早是不知道位置、按 HUD 时间在内存里找到的（`turbo.locate`，现在是后备）。
v1127（2026-11-12）实测：
- 和 HUD 时间对得上、并随时间走的槽有 78 个，其中 54 个是拷贝：给本体加 10 秒，它们一起跳；给拷贝加，下一帧被改回去。
- 给本体加 30 秒，HUD 也跳过去；按 4 倍放大它，计时到 8:00 时首领准时出现，战斗速度不变。
- 选卡、死亡时计时停；HUD 的 `"phase"` 是 `"playing"` / `"dead"`。

本体附近的样子（同一局，计时 482 秒时；以后想用结构指纹直接认出它可以参考）：

```
-0x30  801.95        -0x20  1034.86  1418.64  27.32
+0x00  482.27 (计时)  +0x04  31 (i32)
+0x10  474.38        +0x24  380.04
+0x40  78.84  489.23  1035.50  1419.55  27.32  483.66  504.07  488.88
+0x74  -10.0         +0x84  2.0  1.0
```

**Bevy 虚拟时钟**（`find_clock.py`，研究用，没采用）：exe 是 Bevy 0.18.1。`Time<Virtual>` 资源按特征能唯一找到，整局不搬家：
速度对 `+0x00 relative_speed` / `+0x08 effective_speed`（f64），`-0x10 max_delta`（0.25 秒），`+0x18 wrap_period`（3600 秒）。
写 2.0 后虚拟时钟 2.00x、战斗明显变快，但 HUD 局内时间仍是 1.0x：局内计时不读它。

## 四、定位方法

### 属性块

拿属性行里的 `cm`（暴击伤害）当锚点——`cm` 固定在 `+0x10`，减去 0x10 就是块起点，
再校验 `+0x00≈hp / +0x20≈arm / +0x2C≈area / +0x30≈luck`。

⚠️ **不要用 `hpMax` 当唯一锚点**：属性行滞后于内存，升级瞬间能差 10%。

### 玩家对象

**结构指纹 + HUD 交叉验证**：

1. 在候选基址的 `+0x604 ~ +0x620` 上，七个属性字段必须同时落在合理区间
   （cm 1~20、spd 0.5~20、pick 1~800、xp 0.5~20、arm 0~2、reg 0~5000、area 0.2~30）；
2. 用 HUD 的**击杀数**（±5%）或**金币**（±10%）确认唯一命中；
3. 校验 `当前血 ≤ 最大血`、`1 ≤ 等级 < 200`。

范围要放宽——高等级角色的拾取、回复能到几百，范围设窄了会找不到。

## 五、为什么 `-1/+1` 差分能定字段

游戏里同一时刻只有少数计数器会变，且**只增不减**（击杀、金币、经验）。
所以：

- 找一个**减少 1** 的小整数 → 重抽/放逐这类“剩余次数”；
- 找两个属性行数值同时吻合的槽位 → 金币、等级。

`+0x658`（重抽）和 `+0x1050`（放逐）就是这样定出来的：一个槽位、变化量恰为 1、其余无干扰。
