# 存档格式

存档在 `%APPDATA%\wenilla-rogue\characters.txt`，同目录 `Saves\` 下是游戏自己的定时备份。
工具：[`src/save.py`](../src/save.py)。以下都是实测。

## 加密

文件内容是 `RSE1:` + base64，解开后：

```
nonce (16 字节) | 密文 | tag (20 字节)
```

- `tag = HMAC-SHA1(key, "tag" | nonce | 密文)`，先校验，不对就拒绝读取。
- 密文按 20 字节一块与密钥流异或：`HMAC-SHA1(key, "ks" | nonce | 块序号 u64 小端)`。
- 明文是 UTF-8 文本。

key 是编译进 exe 的常量（42 字节）。exe 里存的是 HMAC 预先算好的 `key^0x36`、`key^0x5c` 两个块，
紧挨着放在 `.rdata`；`save.py` 每次从 exe 里找出这对块，用能通过当前存档 tag 校验的那个作为 key，
所以仓库里不存 key，游戏换 key 也会被发现。

逆向入口：从 exe 里 `RSE1:` 字符串的交叉引用找到解码函数（比较这个头的那个），它调用的就是解密和 HMAC-SHA1 两个函数。地址每次更新都会变，所以不记具体 RVA。

## 明文：一行一个字段

职业编号同 WoW：1 战士、2 圣骑士、3 猎人、4 盗贼、5 牧师、7 萨满、8 法师、9 术士、11 德鲁伊。

| 行 | 含义 | 把握 |
|---|---|---|
| `resets\|N` | 特权重置**已用**次数（共 2 次，页面显示 2−N）。为 0 时游戏不写这一行 | 实测：改 2→0 后页面 0/2→2/2 |
| `marks\|职业\|N` | 该职业的印记，**单位 0.1**（`1440` = 144.0 枚），升级装备用 | 实测：写 99999 显示 9999.9，升级正常扣除 |
| `perk\|名字:等级,...` | 特权等级（`banish` 放逐、`rerolls` 三思、`skip` 跳过、`opening` 开局手牌、`veteran` 老兵的教诲…），已花费点数由此算出 | 实测：确认“跳过”后多出 `skip:1` |
| `ach\|id,...` / `achat\|id=时间戳,...` | 已完成的成就及完成时间；特权点数（成就获得）由成就算出 | 对照页面 |
| `talent\|职业\|经验\|天赋:点数,...` | 该职业的天赋经验和当前加点；天赋点有上限（圣骑士 51 点已满） | 对照 HUD 帧 `"points":51,"next":0` |
| `spec\|职业\|...` | 保存的天赋方案 | 推测 |
| `items\|id,...` / `equip\|职业\|槽位:id,...` | 已收集的装备 / 当前穿戴（`items` 26 个 = 军械库“已收集 26/63”） | 对照页面 |
| `look\|职业\|槽位:id` | 外观 | 推测 |
| `pets\|...` | 已解锁伙伴 | 推测 |
| `beat` / `hbeat` / `coopbeat` | 普通 / 英雄 / 合作模式已通关区域 | 推测 |
| `hero\|职业\|...` | 各职业英雄的数据，末尾是外观 | 部分推测 |
| `stat\|kills=...,marks=...` | 生涯统计（`marks` 同样是 0.1 单位） | 对照 |
| `seen` / `pity` / `glow` / `pick` / `open` | 图鉴计数 / 掉落保底 / 武器发光进度 / 上次选择 / 打开的页面 | 推测，不建议改 |

“推测”的字段改之前先用 `--export` 导出、手工改一行、`--import --dry-run` 看清改动，再在游戏里确认。
成就、装备这类 id 字段写入游戏不认识的值，后果未知。
